# Phase 5: full emit and transpilation

Phase 5 is complete on Windows x64. It implements JavaScript and declaration emission, source maps, every transform and runtime helper supported by the pinned Go revision, output-file handling, incremental declaration signatures, and the single-file transpile APIs. Performance tuning remains deferred.

## Emit foundations

The emission layer owns metadata separately from parsed program nodes. It tracks originals, emit flags, comment and source-map ranges, synthetic comments, and helper dependencies. Generated child rewriting covers all 167 AST shapes with children, preserves unchanged identities and list metadata, and uses the existing runtime-async stack guard. The generator also imports all 25 emit flags and 27 runtime helpers from the Go source, including helper dependencies and scoped text factories.

The UTF-8 writer tracks generated lines and UTF-16 columns for source-map consumers. The version-3 map generator preserves source/name interning, relative paths and URLs, source contents, pending segment behavior, and base64 VLQ deltas. Source-map column decoding follows the reference's treatment of invalid UTF-8 bytes; compiler syntax positions remain byte offsets.

The [foundation comparison](../csharp/compatibility/evidence/phase5-emission-foundations.json) covers 378 cases: 377 strict matches and one reviewed difference, with zero unexplained failures. This includes 92 generated-name scenarios covering scope reuse, reservations, collision avoidance, private names, clone identity, and declaration-derived names. Release safety checks cover original-node isolation, metadata copies, cancellation, helper dependency ordering, Unicode columns, and rewriting at depth 20,000.

Reproduce with `node csharp/tools/generate-emission.mjs --check`, `node csharp/tools/emission-foundations.mjs --dotnet <dotnet.exe> --record`, and the Release compatibility harness's `--emit-foundations-safety` command.

## Syntax printer

The new printer emits parsed and transformed syntax through an explicit work stack, retaining original comment and mapping ranges without mutating program nodes. Its current [comparison gate](../csharp/compatibility/evidence/phase5-printer.json) has 2,296 cases: all 553 parsed-syntax fixtures extracted from the pinned Go printer tests, expression and type precedence combinations on trees with parentheses removed, generated names across declaration scopes, comment-filtering cases, and source maps. Additional cases cover helper priority and suppression, directive prologues, trailing-semicolon omission, JSON output, and declaration references. There are 2,291 strict matches and five individually recorded semantic corrections, with zero unexplained failures. Release safety checks also print a depth-20,000 tree and verify cancellation, printer reuse, and original-tree isolation.

Reproduce with `node csharp/tools/printer-corpus.mjs --dotnet <dotnet.exe> --record`.

## Type erasure and transform environments

Type erasure removes type-only declarations, annotations, assertions, overloads, and type-only import/export bindings while retaining runtime TypeScript constructs. Import elision uses the existing checker reference queries on original parse nodes. The printer restores parentheses when comments in erased assertion wrappers would otherwise change automatic semicolon insertion after `return`, `throw`, or `yield`.

The rewriter now supports statement expansion and variable and lexical environments. Generated visitor hooks handle source-file statements, function parameters and bodies, embedded statements, and loop bodies. When a parameter initializer introduces a temporary variable, its initialization moves into the function body. Concise arrow bodies become blocks when required, and generated declarations merge after directive prologues in the reference's prescribed order.

The [transform comparison](../csharp/compatibility/evidence/phase5-transforms.json) has 7,245 cases: 7,005 strict matches, 240 recorded corrections to reference bugs, and no unexplained differences. It includes all 69 type-erasure and 20 import-elision fixtures extracted from the reference tests, both with and without maps, plus comment, decorator, option, and environment cases. The 857 Node execution probes check comment-sensitive expressions, enums, namespace references, parameter properties, destructuring and operator evaluation order, decorator application, async functions, async generators, iterator cleanup, resource disposal, class initialization, and module bindings. The 137 Release safety assertions include original-tree isolation, cancellation during a visit, environment restoration, and transformation and printing at depth 20,000.

Reproduce with `node csharp/tools/printer-corpus.mjs --transforms --dotnet <dotnet.exe> --record`.

## Runtime TypeScript syntax and metadata

Enums emit their runtime objects and numeric reverse mappings using checker-computed member values. Namespaces emit closures, merge repeated declarations, qualify exported references, and preserve shadowing. Constructor parameter properties create fields and assignments after the first supported `super()` statement, including nested `try` blocks. Shared destructuring lowering handles defaults, computed names, object rest, and temporary declarations.

Decorator metadata is serialized before type erasure. It uses the checker's type-reference classification, runtime constructor checks for unresolved names, accessor pairing, and metadata helper requests. The comparison includes metadata combined with import elision and namespace lowering, strict-null behavior, and pre-ES2020 BigInt constructor checks.

Legacy decorators preserve constructor replacement through class aliases, evaluate computed member names once, pair accessors, order parameter decorators before metadata, and retain private-name access inside static blocks. The 224 decorator comparisons cover ES2015 and ES2022 output with metadata and source maps; execution probes check constructor identity, nested classes, static initialization, evaluation order, and descriptor replacement.

## Expression and supporting transforms

Target-dependent lowering handles exponentiation, logical assignments, nullish coalescing, optional chaining, and omitted catch bindings. It preserves receiver binding through optional and parenthesized calls, short-circuit evaluation, computed targets, and temporaries introduced in parameter initializers. The 428 comparisons cover target boundaries from ES2015 through ESNext; safety checks lower and print an optional chain with 20,000 links.

Const-enum inlining uses checker-computed values and safely escapes original expression text in synthetic comments. Strict-mode directive insertion follows the file's module format. Tagged templates with invalid escapes produce cooked and raw arrays, normalize raw line endings, and cache template objects in modules. These supporting transforms have 330 additional comparisons, including source maps, comment removal, isolated-module behavior, and nested templates.

Object rest and spread lowering preserves getter order through nested `Object.assign` calls, lowers binding and assignment patterns, retains assignment results, and handles computed keys and symbols. Parameter lowering moves later initializers into the body in evaluation order; catch bindings and `for...of` bindings receive generated locals. The 255 comparisons include 27 execution probes and cover both transformed and retained syntax at the ES2018 boundary.

Async function lowering preserves default-parameter evaluation and rejection, function length, lexical `this` and `arguments`, nested arrows, parameter redeclarations, and catch scopes. Shared super-access lowering captures property getters and setters, indexed reads and writes, and method receivers. The 285 comparisons include 33 execution probes; separate safety checks transform and print 20,000 nested awaits and convert binding patterns of the same depth.

Async iteration lowering handles `for await`, labeled and nested loops, delegated yields, and iterator closing through `break`, `return`, and thrown errors. Async generators preserve parameter timing, function length, incoming values, mapped arguments, and `super` access in bodies and parameter defaults. Its 285 comparisons include 75 execution probes across ES2015, ES2017, and ES2018; safety checks also transform and print 20,000 nested awaits inside an async generator.

Resource-management lowering emits registration and disposal for `using` and `await using`, handles ordinary and async loops, and keeps imports and exports at the top level. The 337 exact comparisons include 57 execution probes covering reverse disposal order, thrown values, suppressed errors, initializer failures, disposer receivers, and async cleanup. A separate safety check lowers a resource initializer nested 20,000 levels deep.

Class-field lowering covers public and private fields, private methods and accessors, auto-accessors, and static blocks. The 1,384 comparisons include 286 execution probes for constructor insertion after `super()`, parameter properties, descriptors, computed keys, loop scoping, class references, brand checks, and legacy decorator integration. Static `super` operations preserve receivers and assignment results; short-circuit assignment and parenthesized calls retain native behavior where the reference does not. Safety checks lower and print a private-field initializer nested 20,000 levels deep.

ECMAScript decorator lowering preserves evaluation order, class replacement, computed names, context access objects, private member descriptors, and metadata inheritance. Extra initializers run at the appropriate class or constructor boundary, including constructors with `super()` inside nested `try` blocks. The 663 comparisons include 99 execution probes across ES2015, ES2022, and ESNext, both class-field modes, and source maps. The safety checks also transform a decorator expression nested 20,000 levels deep. Class-field integration preserves the captured constructor and assigned class name, including static private storage that must be lowered even at ESNext.

JSX emission supports classic factories, automatic production and development runtimes, fragments, namespaced names, key fallback, and both retained and lowered attribute spreads. It preserves factory pragmas, namespace qualification, runtime import ordering, entity decoding, whitespace rules, and development locations in UTF-16 columns. The 652 exact comparisons include 90 execution probes, the complete reference entity table, import-elision integration, and source maps. Safety checks verify generated import references, transformer reuse, original-tree ownership, and 20,000 nested JSX elements.

Module emission implements the reference's ES and CommonJS transform selection, including per-file formats from Node extensions and package metadata. It handles import and export bindings, re-exports, namespace imports, helper imports, dynamic imports, relative-extension rewriting, and Node `createRequire` generation. Its 1,850 comparisons include 110 execution probes and 84 integration cases with decorators, class fields, resource disposal, async iteration, namespaces, and JSX. The strict-mode and module transforms share the program's file-format resolver. Safety checks exercise transformer reuse and 20,000-level expression and assignment patterns.

Module aliases remain live through assignments, updates, destructuring, and loop targets. Native destructuring uses setter targets for aliases so iteration, defaults, evaluation order, and abrupt completion retain their JavaScript semantics. Integration checks also verify generated iterator declarations when their base names match parameters, and anonymous class names when private storage is lowered.

## Declaration emission

Declaration transformation now uses checker-built syntax for inferred types and signatures. It preserves required imports, tracks accessibility and isolated-declaration diagnostics, emits overloads, parameter properties and late-bound members, and handles JavaScript documentation types, CommonJS exports, function properties, references, and declaration maps. Inference callbacks restore checker scope on cancellation, and emitted syntax remains independent of both parsed nodes and cached type syntax.

The [declaration comparison](../csharp/compatibility/evidence/phase5-declarations.json) covers 428 authored cases: 422 strict matches and six reviewed corrections, with no unexplained differences. The [consumer checks](../csharp/compatibility/evidence/phase5-declaration-consumers.json) compare 22 original-source and emitted-declaration consumers in both checkers. Separate safety checks verify source ownership, cancellation inside a checker query, transformer reuse, and emission at depth 20,000.

The [compiler-fixture comparison](../csharp/compatibility/evidence/phase5-emit-fixtures.json) covers all 1,760 active exported compiler configurations that enable declaration or composite output, including three content-mapper cases. It compares the complete source graph, JavaScript and declaration outputs, maps, diagnostics and callback metadata. There are 1,758 exact matches and two independently checked runtime corrections, with no unexplained failures or skipped cases in this selection. Mapper cases cover supplemental declarations, relative references and map composition.

Reproduce the fixture gate with `node csharp/tools/program-emit-fixtures.mjs --declarations --dotnet <dotnet.exe> --record`. It consumes the source blobs exported by the semantic-corpus gate; `--reference-directory` selects another export. Use `--retry <tag>` to repeat the failed cases of an earlier run. The runner records binary hashes before and after execution and rejects a run if its binaries changed.

JSDoc import range corrections bring 154 fields in 34 documentation cases into agreement with the reference. The [controlled comparison](../csharp/compatibility/evidence/phase5-jsdoc-import-ranges.json) retains before-and-after results and verifies that no previously matching field regressed. The older documentation gate already had 798 unexplained failures with the original parser files; its current policy reports 801 because three corrected cases no longer match their previously approved hashes. No existing phase-2 policies were rewritten, and this is not a passing documentation gate.

## Program emission

The program API now runs the script and declaration pipelines, selects target files, checks output collisions, and supports declaration-only, forced, and builder-signature emission. Its write callback receives source-file identity, diagnostics and the map URL position, and can suppress an unchanged declaration write. File-system write failures become emit diagnostics. Output paths cover Node extensions, JSX, JSON, separate declaration directories, and content-mapped files.

Source-map output handles external and inline maps, source roots, map roots, Unicode URL encoding, BOMs and newline options. Declaration maps compose exact mapper positions with the original source; unmapped ranges emit generated-only segments. Canonical mapped declarations reference the emitted supplemental declarations.

The [program comparison](../csharp/compatibility/evidence/phase5-program-emit.json) has 240 exact matches, including callback metadata, failures, collisions, target selection, complete transform pipelines and 36 config-diagnostic cases. Diagnostics preserve ordering between config, syntax, program, global, semantic and declaration groups, including message chains and source positions. Callback records are compared by output path because the reference may invoke callbacks concurrently; the emitted-file and source-map result arrays retain their original order. Eighteen safety assertions cover repeated emission, cancellation during writes, immutable program ownership, mapped outputs, and declaration signatures across implementation-only and public-type edits.

Intermediate development builds used `-p:RunAnalyzersDuringBuild=false -p:UseSharedCompilation=false` after a diagnostic stack showed the SDK trimming analyzer occupying the compiler for over ten minutes. Project analyzer settings remain enabled. The final Release solution build uses the normal analyzers and succeeds with zero warnings and errors. Development logs retain an earlier compiler CLR failure and a file-copy contention run; subsequent builds use separate output directories.

## Single-file transpilation

`Transpiler.TranspileModuleAsync` and `Transpiler.TranspileDeclarationAsync` create isolated programs in memory, clone and override compiler options, and return output text, source-map text and diagnostics. Declaration transpilation supplies the reference's minimal library and reports isolated-declaration errors even when optional diagnostic reporting is disabled. Program construction can skip package, import, type-reference and library-reference resolution while retaining the default library.

The [transpile comparison](../csharp/compatibility/evidence/phase5-transpile.json) has 415 exact matches, including all 83 cases extracted from the reference transpile runner and its option matrices. It covers JavaScript and declaration output, unresolved imports, arbitrary extensions, Node formats, JSX, source maps, Unicode source contents, option overrides, parse errors and option diagnostics. Twelve safety assertions cover input-option ownership, concurrent calls, cancellation, repeatable output and declaration-input rejection. These comparisons also found and fixed inferred declaration scope, required initialized parameter types, and computed-symbol serialization issues.

Reproduce with `node csharp/tools/transpile-corpus.mjs --dotnet <dotnet.exe> --record` and the Release harness's `--transpile-safety` command.

## Intentional differences

`writer-chunked-crlf` applies only to the recorded `writer-split-crlf` fixture. Writing `a\r`, then `\n`, then `b` produces the same bytes in both implementations. Go reports the last character on zero-based line 2 because it counts the split CR and LF independently; C# reports line 1. An independent Node runtime lookup reports `chunked-crlf.js:2:1`, confirming C#'s position. The evidence record retains the input and source hashes, both complete results, the policy name, and the runtime evidence. No other fields or cases are normalized by this policy.

`preserve-binary-association` applies only to the five recorded runtime fixtures. Go flattens a right-nested multiplication, addition of numeric literals, and the three bitwise binary operators. C# retains the parentheses. Node execution establishes that flattening changes the floating-point results (`0` to approximately `1e-308`, and `10000000000000002` to `10000000000000000`) or the observable operand-conversion order (`c, b, a` to `a, b, c`). Each case checks the exact parenthesis-only output difference and retains the source and case hashes, both emitted outputs, and independent original/reference/candidate runtime results.

`preserve-async-arguments-property-name` retains the `arguments` key when the value is captured into a generated variable. The reference emits `{ arguments_1 }`, changing the key; C# emits `{ arguments: arguments_1 }`. A Node probe checks the property's presence in native JavaScript and both emitted programs. Every recorded case requires exactly that text substitution and retains both source maps.

`preserve-async-parameter-scope` omits generated local declarations that would hide an incoming parameter in the outer function. The reference's duplicate `var` changes an incoming value of `42` to `undefined`, including when the declaration occurs in a catch clause; reading it in an initializer can instead produce `NaN`. Native JavaScript and C# emission retain the incoming value. Each recorded case checks the bounded declaration changes, retains both outputs and maps, and links the execution evidence.

`preserve-async-generator-parameter-scope` forwards simple parameters into the generated function so `var` redeclarations and mapped `arguments` retain the original binding. The reference can produce `undefined`, `NaN`, or a stale argument value. Each recorded difference permits only an added parameter list matching the original syntax or the corresponding outer wrapper after earlier transforms.

`preserve-async-generator-arguments-parameter` renames the outer parameter when it is named `arguments`, keeping the actual arguments object available for forwarding. The reference instead passes the parameter value to `Function.apply` and throws. `preserve-async-generator-super-parameter` captures `super` in default parameters before moving them into the generated function; the reference output fails to parse. These policies check exact output substitutions for the recorded probes and retain complete output, map, and native/reference/candidate execution evidence.

`preserve-class-logical-assignment` keeps private and static `super` setters inside the short-circuit branch. The reference invokes the setter even when the original value should be retained. `preserve-parenthesized-class-call-receiver` preserves receiver binding through parentheses around private or static `super` calls and template tags; the reference loses the receiver and throws in the recorded probes. The checks permit only the specified expression substitutions and retain both outputs, maps, and native/reference/candidate execution results. Logical-assignment probes cover both the skipped and taken branches.

These two policies also cover decorated classes with static `super` operations. Their independent controls remove only the no-op class decorator, so Node can execute the corresponding native class semantics. `register-forced-static-accessor-storage` covers the reference assertion failure for class decorators combined with a static auto-accessor at ESNext and `useDefineForClassFields: false`. Each recorded case requires the exact assertion message and a complete text match against an ES2022 reference control, allowing only the specified retained instance accessor. A separate execution probe verifies static initialization, replacement, reading, and writing. The oracle bridge records a panic as a failed result for its input; it does not modify reference compiler behavior.

The [module correction manifest](../csharp/compatibility/module-corrections.json) permits 95 reviewed differences, each bound to exact hashes of its input and both output-and-map records. These preserve the receiver of parenthesized imported calls, read the actual export after postfix updates, resolve export aliases by declaration identity, update aliases in loop targets, retain native destructuring, and preserve inferred function and class names. Every record links an independent native ES-module probe; a self-import observes the original module's live exports. Reference errors and incorrect results are retained alongside native and candidate results. The manifest cannot admit a changed input, output, or map automatically.

The [declaration correction manifest](../csharp/compatibility/declaration-corrections.json) records four function-property cases where adding an alias export must retain earlier properties as exported namespace members. Both checkers accept the original source and corrected declarations; the reference declaration loses the earlier property and produces diagnostic 2339 in a consumer. Two further cases preserve a negative numeric property assigned through `this`; the reference throws during declaration generation. Both checkers accept the corrected property declaration. Every permitted difference is bound to the exact input, output, map and consumer-evidence hashes.

The [compiler-fixture correction manifest](../csharp/compatibility/emit-fixture-corrections.json) binds the two broad-fixture differences to exact input and complete output hashes. `dependentDestructuredVariables.ts` uses the same async-generator parameter preservation verified by the transform probes. `privateFieldsInClassExpressionDeclaration.ts` retains an anonymous class's inferred binding name; native JavaScript and the candidate retain `ClassExpression`, while the reference changes it to `_a`. Both fixtures retain independent execution controls and all source, declaration and map outputs.
