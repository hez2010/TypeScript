# C# language services

The C# backend implements completions and auto-imports, code actions and import organization, hover, signature help, definitions, type and source definitions, references, Visual Studio grouped references, implementations, document highlights, rename, prepare rename, file renames, call hierarchy, CodeLens, inlay hints, JSX closing-tag insertion, pull diagnostics, smart selection, JSX linked editing, folding ranges, document and workspace symbols, semantic tokens, and document, selection, and on-type formatting. `--lsp` serves these queries through the project session, with document open/change/save/close notifications and UTF-8 or UTF-16 position negotiation. Initialization advertises the implemented providers. The [phase-7 report](csharp-phase-7-progress.md) records the final gates, and the [project report](csharp-project-services.md) covers the original-test inventory and lifecycle contracts.

`textDocument/diagnostic` returns complete reports containing syntactic, semantic, suggestion, and declaration diagnostics in the reference order. Validation and style-warning preferences apply at the snapshot boundary. Related information, unnecessary/deprecated tags, Visual Studio diagnostic codes, and diagnostic localization follow the negotiated client settings. Mapped diagnostics use original coordinates and alias names; problems entirely in synthesized code appear in one aggregate per projected file, with the original messages as related information. Mapper failures and mapper-supplied diagnostics retain their own presentation. Changed diagnostic preferences request a refresh only when the client supports it; a pending refresh response does not block other requests or shutdown.

Configured projects publish parsing, program, and newly discovered global diagnostics on their configuration URI. Snapshot transitions preserve the reference's publication order, single-file update behavior, and config-parser diagnostic lifetime. Opening, closing, and reopening sources publishes or clears those reports; watched config changes update them without requiring a client query. Push-disable negotiation, validation preferences, locale, related information, tags, and Visual Studio codes apply to these notifications. Watched source changes request a debounced diagnostic refresh, mapped edits request an immediate coalesced refresh, and ordinary edits cancel pending refreshes. Shutdown cancels delayed updates, pending refresh requests, and publication work; queued notifications own only their serialized payloads.


Compiler source text and AST positions remain UTF-8. `DocumentLineMap` converts positions at the LSP boundary; its line boundaries follow LSP rather than the compiler's ECMAScript line map. `LanguageServiceDocument` includes canonical and supplemental content-mapper outputs, checks each feature's mapping permissions, and maps results to the original document. Selection requires one exact or atom projection; linked editing requires one exact projection and exact output ranges. Folding visits every projection, discards unmapped ranges, and removes duplicate results.

Selection retains the innermost ranges and the outer source range within a 1,000-level limit. Its temporary mapped-type groups do not change AST parents. Folding uses an explicit traversal stack, with the reference depth limit and its exceptions for chained calls and `else if` statements. It preserves comment groups, regions, JSX banners, import groups, malformed-source recovery, and the client's collapsed-text and line-only folding options.

Semantic tokens use exclusive project checker leases. They classify declarations and references, resolve aliases, distinguish callable and constructable types, and preserve local, readonly, static, async, and default-library modifiers. Full and range queries negotiate the client's token legend. Only exact mappings produce encoded tokens; duplicate start positions from multiple projections produce one entry. Traversal uses an explicit stack.

`SourceFormatter` produces byte-range edits without changing token spelling or the input tree. It supports spacing and brace preferences, semicolon insertion/removal, comments, JSX, incomplete syntax, and indentation inherited from existing source. Its 135 declarative token-pair rules are generated from the pinned reference; scanning, context evaluation, indentation, and edit production are managed implementations. `SmartIndenter` also exposes indentation queries. Deep formatting resumes on a fresh stack when required.

Mapped formatting processes only verbatim segments with formatting enabled. Overlapping projections prefer the earliest, then longest mapping; edits outside an accepted segment are discarded. On-type formatting requires one exact projection and exact output edits. Formatting preferences follow editor, JavaScript, TypeScript, and `js/ts` precedence; stable settings override raw and unstable settings. Immutable preferences travel with project snapshots, including snapshots retained by connected API clients.

Call hierarchy resolves named declarations, assigned expressions, overload implementations, merged signatures, classes, accessors, and static blocks. Incoming calls use the shared cross-project reference search; outgoing calls use an explicit syntax stack and retain the reference rules for nested declarations, decorators, JSX, computed names, and ambient code. Both directions group call sites by declaration, preserve their ranges, and merge projected items by original document and selection range. Items and ranges respect call-hierarchy mapping permissions. Returned items contain no syntax or checker references.

CodeLens enumerates references and implementations according to the five client preferences, collapses overloads, and preserves the raw position and supplemental-file identity needed for resolution. Resolution uses the shared cross-project search, excludes declarations from reference counts, and removes the origin from implementation results. Counts and optional navigation commands preserve their distinct absent and empty values. Changed CodeLens preferences request a refresh when the client supports it; pending refresh responses do not block requests, and shutdown cancels that work.

Inlay hints cover parameter names, inferred variable, property and parameter types, return types and predicates, and enum values. Type labels retain individual parts and optional navigation targets. Tuple spreads and rest parameters preserve their source labels; comments and matching argument names suppress redundant hints. Name/type suppression uses the Go Unicode fold tables. Intersecting source projections contribute hints in reference order, including duplicates; name targets require a single mapped span. Configuration controls each hint category and requests supported client refreshes without blocking queries.

JSX automatic insertion returns closing-tag snippets for unclosed elements and fragments, including nested matching tags. It reconstructs compound tag names without trivia, retains identifier spelling, and escapes dollar signs in snippet text. Only one exact, enabled mapping may contribute an insertion. The auto-closing preference supports the stable setting and its legacy boolean fallback.

LSP messages execute in arrival order, while the RPC read loop continues accepting callback responses and cancellation notifications. Requests therefore observe preceding document changes without absorbing later edits. The current implementation serializes request execution. Shutdown joins handlers and releases the project session; `exit` completes even when Windows console input does not cancel its pending read and the editor leaves the pipe open.

`custom/initializeAPISession` binds a JSON-RPC pipe connected to the editor's project session. API clients can retain the current editor snapshot or create independent branches from it. Each client owns its project/file opens and synthetic programs; disconnect releases those references while preserving editor documents and other clients' resources. Invalid updates do not become canonical snapshots, and pending editor changes still advance. Shutdown closes connected clients and listeners awaiting their first connection.

Document symbols support hierarchical outlines and flat symbol lists. They retain declaration names, callbacks, destructuring, JSDoc typedefs, JavaScript property assignments, and merged namespaces. Mapped names must fit a single segment with document symbols enabled; an unmapped declaration range falls back to its mapped name range. Duplicate top-level symbols from multiple projections are removed.

Workspace symbols collect declarations across active projects, collapse overload groups, and rank Unicode subsequence matches with case-sensitive uppercase characters. Results retain name spans and containers, with a 256-result limit applied before mapped-range filtering. Configuration controls library exclusion and current-project scope; searching all projects loads referenced project trees while respecting disabled reference loading. Supplemental symbols navigate to their canonical document.

Insertion formatting prints a factory tree while recording node, token, and list positions, then formats a separate positioned copy using the target document's indentation. It preserves the caller's tree and reads formatting preferences from the pinned API snapshot. Symbol-reference queries within a file resolve declaration identities, shorthand assignments, and export aliases through the exclusive checker lease.

Hover resolves contextual properties, aliases, overloads, and documentation through the exclusive checker lease. It supports Markdown and plain text, linked JSDoc, verbosity expansion with library and cycle boundaries, configurable truncation, and Visual Studio classified text and icons. Exact and atom projections contribute results; duplicate content is removed, and a shared range is retained only when all projections agree. Documentation links use the target file's mappings, including supplemental sources.

Definition queries select overloads, resolve contextual object and binding properties, and navigate keywords and labels. Type definitions follow inferred function return types and recognized generic type arguments. Results use the client's location-link capability, retain declaration context, and combine content projections with declaration maps. Source definitions follow declaration maps, resolve implementation modules and forwarded exports, and parse files outside the program without changing its graph. The source-definition preference redirects ordinary definition requests through the same provider.

Reference search follows aliases, imports, exports, contextual and inherited properties, constructors, labels, literals, and JSDoc names. Implementation queries reuse the search engine and expand inherited results. Cross-project searches retain snapshot and checker leases, load relevant project trees, and follow declaration maps in both directions. Results preserve feature-specific content mapping and declaration filtering.

Visual Studio references retain definition groups, classified text, read/write kinds, project names, and unique IDs across projects. Document highlights use the same symbol search with a selected set of files, and classify declarations, assignments, and reads. Syntactic highlights cover control-flow keywords, accessors, modifiers, and paired JSX tags. Multi-document responses combine mapped projections and remove duplicate ranges.

Rename validates declarations, standard-library and package boundaries, import-path capabilities, and exact writable mappings. It preserves shorthand and import/export aliases according to the client preference, follows declaration maps to source edits, and rejects conflicting mapped edits. File renames load the project trees, update import specifiers, triple-slash references and tsconfig paths, preserve extension preferences, and include related source-file renames for declaration files. Mapped file changes are atomic: any unmappable or conflicting projection drops the affected file's edits. Workspace edits retain the client's document-change and resource-operation capabilities.
